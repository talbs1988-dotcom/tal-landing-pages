# שלב 5 — בדיקה

קודם לקרוא ולעבוד לפיה: החוקה, `<Base directory של הסקיל הזה>/../../references/stage-contract.md`.

**"נראה עובד" זה לא "עובד".** כל שורה בדוח נשענת על משהו שנבדק עכשיו: פלט, מספר, צילום מסך, קוד תשובה. מה שלא נבדק כתוב "לא נבדק", ולמה. אף פעם לא ✅ על משהו שלא נבדק.

## נתיבים ושמות בפקודות

- `$SCRIPTS` = `<Base directory של הסקיל הזה>/../../scripts` (התיקייה). זה **קיצור בלבד**, לא משתנה של הטרמינל. משתנים לא עוברים מפקודה לפקודה, אז בכל פקודה כותבים את הנתיב המלא, למשל: `node '<Base directory של הסקיל הזה>/../../scripts/status.mjs' …`.
- כל נתיב, שם או הערה בפקודה עוטפים בגרש בודד: `'דנה בע"מ'`.
- נתיב או שם שיש בו גרש (') — לכתוב אותו כ-`'\''`. למשל `צ'יפס` נכתב `'צ'\''יפס'`.
- `<האתר>` = `<תיקיית הדף>/site`. `<הבדיקות>` = `<תיקיית הדף>/4-checks`.
- `<כתובת>` = `http://localhost:3210` (או הפורט שבאמת עלה, ראו ה).

## איך מדברים עם בעל העסק

- לפי השורה "פנייה לבעל העסק" ב-CLAUDE.md. לא מולאה → ברבים.
- כל ממצא מוסבר במילים של בעל עסק: מה ראינו, מה זה אומר לגולש, ומה עושים. לא "overflow" ולא "axe violation". הטבלה ב"ממצאים במילים פשוטות" למטה.
- בלי דפוסי ה-AI שבסעיף 6 של `references/writing-rules.md`, גם בשיחה ובדוח.

## ו. בדיקות החובה בדפדפן

בכל בדיקה: קודם `localStorage.clear()` ורענון, כדי שהבחירה בבאנר העוגיות לא תישאר מבדיקה קודמת.

1. **6 רוחבים בלי גלילה הצידה:** 320, 375, 414, 768, 1024, 1440 (גובה 900). לכל רוחב: לשנות גודל, לרענן, ולהריץ:
   ```js
   (() => {
     const d = document.documentElement;
     const wide = [...document.querySelectorAll("body *")]
       .filter((e) => e.getBoundingClientRect().right > innerWidth + 1)
       .slice(0, 5)
       .map(
         (e) =>
           e.tagName.toLowerCase() +
           (e.id ? "#" + e.id : "") +
           "." +
           [...e.classList].slice(0, 3).join("."),
       );
     return { extra: d.scrollWidth - d.clientWidth, wide };
   })();
   ```
   `extra` גדול מ-0 → נכשל ברוחב הזה, ו-`wide` אומר מה בורח. צילום מסך של כל רוחב: `<הבדיקות>/home-<רוחב>.png`.
2. **נגישות (axe):** על `/`, `/terms`, `/privacy`, `/accessibility`, `/data-deletion`, ברוחב 375 וברוחב 1440. אחרי ההזרקה:
   ```js
   (async () => {
     const r = await axe.run(document, { resultTypes: ["violations"] });
     return r.violations
       .filter((v) => ["critical", "serious"].includes(v.impact))
       .map((v) => ({
         id: v.id,
         impact: v.impact,
         help: v.help,
         nodes: v.nodes.length,
         first: v.nodes[0]?.target,
       }));
   })();
   ```
   עובר רק כשהרשימה ריקה בכל הדפים. הפרות קלות (`moderate`, `minor`) נרשמות בדוח, לא חוסמות.
3. **כל כפתור מוביל לטופס:** ב-375 וב-1440. טקסט הכפתור = `hero.cta` ב-`<האתר>/content/copy.json`. לכל כפתור בדף שזה הטקסט שלו: לגלול אליו, ללחוץ, לחכות שנייה, ולבדוק:
   ```js
   (() => {
     const f = document.getElementById("lead-form");
     const r = f.getBoundingClientRect();
     return {
       focusInForm:
         !!document.activeElement?.closest("#lead-form") ||
         document.activeElement === f,
       visible: r.top < innerHeight && r.bottom > 0,
     };
   })();
   ```
   שני הערכים `true` בכל כפתור → עבר. לרשום כמה כפתורים נבדקו. יש בדף קישור או כפתור שמוביל למקום אחר (לא לטופס ולא לדף משפטי) → לרשום אותו.
4. **הפיקסל לא יורה לפני הסכמה** — רק אם יש מזהה פיקסל: ב-CLAUDE.md, ב-`5-connect/connections.md`, או שבעל העסק נתן אותו. **אין מזהה** → בדוח "➖ לא רלוונטי: אין פיקסל בבנייה הזו. נבדק ב-`/page-connect`", וזה לא חוסם. **יש מזהה** (הוא לא סוד, הוא מופיע בכל דף שיש בו פיקסל):
   - לעצור את האתר, לבנות עם המזהה: `cd '<האתר>' && NEXT_PUBLIC_META_PIXEL_ID=<המזהה> npm run build`, ולהפעיל שוב כמו ב-ה.2.
   - לפתוח את הדף אחרי `localStorage.clear()`, לחכות 3 שניות, ולבדוק ברשת שאין שום בקשה ל-`connect.facebook.net` או ל-`facebook.com/tr`, ושה-`window.fbq` לא קיים.
   - ללחוץ "אישור הכול" בבאנר, ולבדוק שעכשיו כן יש בקשה ל-`connect.facebook.net`. ככה יודעים שהבדיקה עצמה עובדת.
   - בסוף לבנות שוב בלי המזהה (`npm run build`), כדי שהבנייה המקומית תחזור למצב הרגיל.
5. **ליד בדיקה:** לפתוח `<כתובת>/?utm_source=page-check&utm_campaign=check`, לדחות עוגיות, ולמלא בטופס: שם `ליד בדיקה`, מייל `check@example.com`, טלפון `0501234567` (אם יש שדה טלפון). לא לסמן את תיבת הדיוור. לשלוח.
   - עבר כשהדפדפן עבר ל-`/thank-you`, **וגם** `<הבדיקות>/test-lead.json` מכיל ליד עם `name`, `email`, `phone`, `marketingConsent: false`, `utm_source: "page-check"`, `utm_campaign: "check"`, `eventId` ו-`pageUrl`. צילום מסך של דף התודה: `<הבדיקות>/thank-you.png`.
   - הגיע לדף התודה ולא לקולט → נכשל ("הגולש רואה תודה, אבל הליד לא יצא מהאתר").
6. **הדפים המשפטיים והפוטר:** `curl -s -o /dev/null -w '%{http_code}'` על `/terms`, `/privacy`, `/accessibility`, `/data-deletion`, `/sitemap.xml`, `/robots.txt` → כולם 200. ובדף הראשי יש קישורים לארבעת הדפים המשפטיים.

### בלי דפדפן (curl)

## ח. מתקנים ובודקים שוב

1. **מה מתקנים לבד** (ואז מריצים שוב את הבדיקה שנכשלה, ובסוף את `npm run check` כולו):
   - גלילה הצידה: מוצאים את האלמנט מ-`wide`, ומתקנים את ה-CSS שלו ב-`components/sections/` או ב-`app/page.tsx` (למשל `max-w-full`, `break-words`, `min-w-0`, רוחב קבוע שהופך ל-`w-full`). לא נוגעים ברכיבים שב"אסור להוריד" של `TEMPLATE.md`.
   - הפרות axe בקוד של הסקשנים: טקסט חלופי חסר (מ-`img.<שם>` ב-copy.json, ואם אין: `[למלא]`), כותרות שקופצות רמה, כפתור בלי שם, שדה בלי תווית.
   - פיסוק בקופי: נקודה בסוף כותרת, כפתור או בולט → מוחקים אותה. מקף ארוך → פסיק. מירכאות מסולסלות → ישרות. ב-`copy.json` וגם ב-`2-copy/copy.md`, כדי ששניהם יגידו אותו דבר.
   - תמונה מעל התקרה, שהמקור שלה ב-`images-inbox/` או ב-`brand/` → `npm run images -- '<מקור>' <שם> --role <hero|inline> --force`.
   - בנייה או בדיקה שנכשלה בגלל קוד שנכתב בשלב העיצוב.
2. **סבבים:** עד 3 סבבי תיקון. אחרי 3 עוד משהו נכשל → לעצור, ולהסביר לבעל העסק מה נשאר ולמה.
3. **מה לא מתקנים לבד** (נכנס ל"מה רק את/ה יכול/ה להחליט"):
   - מילים בקופי (דפוס AI, טקסט כפתור שונה, "כולל מע"מ" אצל עוסק פטור). מציעים נוסח ומחכים לאישור. אישר → מתקנים ב-copy.json וב-copy.md, ובודקים שוב.
   - `[למלא]` של פרט שרק בעל העסק יודע: פרט עסקי (→ `/page-legal`), מספר, תמונה, טקסט.
   - צבעי המותג, כשהניגודיות נכשלה בגלל הצבע עצמו. מציעים גוון קרוב שעובר.
   - בדיקה שלא הייתה אפשרית (אין דפדפן) והאם להמשיך בלעדיה.

## ט. סיום

1. **לעצור את השרתים:** האתר (ה.2) והקולט (ה.1). לבדוק ש-`curl -s -o /dev/null -w '%{http_code}' '<כתובת>/'` כבר לא מחזיר 200.
2. להראות לבעל העסק: שורת התוצאה, טבלת החובה כמו שהיא ב-report.md, מה תוקן, ומה רק הוא יכול להחליט. כל ממצא לפי "ממצאים במילים פשוטות".
3. **אסור להריץ `set check done` כשיש ❌ בבדיקת חובה.** לא "כמעט עבר", לא "זה קטן", ולא גם אם בעל העסק מבקש. במקרה כזה: `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' check doing 'נכשל: <מה>. ממתין ל: <מה צריך>'`, ולומר מה הצעד הבא.
4. **⚠️ לא נבדק בבדיקת חובה** (למשל אין דפדפן) → גם אז לא מסמנים אוטומטית. מסבירים מה לא נבדק ומה הסיכון, ושואלים: "להתקין את Playwright ולבדוק הכול, או להמשיך בלי הבדיקות האלה?" רק אישור מפורש של בעל העסק, באותה שיחה, מאפשר להמשיך, וההערה אומרת מה לא נבדק.
5. כל החובה ✅ (או ➖, או ⚠️ שבעל העסק אישר) → לשאול: "הדף עבר את הבדיקה. מאשרים?" ואחרי אישור:
   `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' check done '<משפט אחד: כמה בדיקות עברו, במה נבדק, מה לא נבדק>'`.
6. לסיים: "הדף מוכן לעלות לאוויר. הפקודה הבאה: `/page-live`."

## אסור בשלב הזה

- לסמן ✅ על משהו שלא נבדק, או לכתוב "עבר" בלי ראיה.
- `set check done` כשיש ❌ בבדיקת חובה.
- לשנות מילים בקופי, צבעים, פרטי עסק או טקסט משפטי בלי אישור של בעל העסק.
- לשלוח ליד בדיקה לכתובת שאינה הקולט המקומי, או למלא בטופס פרטים אמיתיים של מישהו.
- לקרוא, להדפיס או לכתוב קבצי `.env`.
- להשאיר שרת רץ בסוף השלב.
