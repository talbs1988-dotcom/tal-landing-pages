# שלב 1 — אפיון

קודם לקרוא ולעבוד לפיהם:

- החוקה: `<Base directory של הסקיל הזה>/../../references/stage-contract.md`
- הראיון: `<Base directory של הסקיל הזה>/../../references/brief-questions.md`
- הקול: `<Base directory של הסקיל הזה>/../../references/voice-profile.md`

## נתיבים ושמות בפקודות

- `$SCRIPTS` = `<Base directory של הסקיל הזה>/../../scripts` (התיקייה). זה **קיצור בלבד**, לא משתנה של הטרמינל. משתנים לא עוברים מפקודה לפקודה, אז בכל פקודה כותבים את הנתיב המלא, למשל: `node '<Base directory של הסקיל הזה>/../../scripts/status.mjs' …`.
- כל נתיב, שם או הערה בפקודה עוטפים בגרש בודד: `'דנה בע"מ'`.
- נתיב או שם שיש בו גרש (') — לכתוב אותו כ-`'\''`. למשל `צ'יפס` נכתב `'צ'\''יפס'`.

## איך פונים לבעל העסק

לפי השורה "פנייה לבעל העסק" ב-CLAUDE.md. לא מולאה — ברבים. השאלות ב-brief-questions.md כתובות ברבים, ומתאימים אותן לפנייה הזו.

## א. איפה אנחנו

לפי צעד 1 בחוקה: `find-root` (ואם לא נמצאה, `find-below` והודעת "פותחים מחדש"), ואז `node '$SCRIPTS/status.mjs' list '<תיקיית העסק>'` ובחירת הדף.

## ב. תנאי כניסה

1. `node '$SCRIPTS/status.mjs' next '<תיקיית הדף>'`. הפלט הוא השלב הראשון שעוד לא אושר.
   - `start` → לעצור: "קודם מסיימים את ההכנה, כי בלי תיקיית דף מוכנה אין איפה לשמור את האפיון. מקלידים `/page-start`."
   - `brief` → ממשיכים.
   - שלב אחר, או `null` → האפיון כבר אושר. לשאול: "האפיון של הדף הזה כבר אושר. לפתוח אותו מחדש?" כן → `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' brief doing 'נפתח מחדש: <למה>'`, ולומר שאחרי השינוי כדאי לעבור שוב על הקופי (ועל העיצוב, אם כבר התחיל). לא → לעצור ולתת את הפקודה של השלב הבא.
2. `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' brief doing` (בלי הערה, כדי שההערה של "איפה עצרנו" תישמר).

## ג. הקבצים של השלב

1. `node '$SCRIPTS/scaffold.mjs' stage-files '<תיקיית הדף>' brief`. הפקודה מעתיקה את `brief.md` ו-`customer-words.md` לתיקייה `1-brief/` רק אם הם לא שם, ולא דורסת כלום. הפלט: מה נוצר (`created`) ומה כבר היה (`skipped`).
2. לקרוא: CLAUDE.md של העסק, `brand/voice.md`, `legal/business.md`, `1-brief/brief.md`, `1-brief/customer-words.md`, ואת ההערה של שלב האפיון: `node '$SCRIPTS/status.mjs' show '<תיקיית הדף>'`.

## ד. מאיפה ממשיכים

- שני הקבצים נוצרו עכשיו → מתחילים מההתחלה: "קודם לחפש, אחר כך לשאול" ב-brief-questions.md, ואז שאלה 1.
- אחרת, נקודת ההמשך היא השאלה הראשונה (לפי הסדר) שכל השורות בסעיף שלה ב-brief.md הן עדיין בדיוק `[למלא]` (שורה עם תווית, כמו `- איך רוצים שיחזרו אלייך: [למלא]`, נחשבת `[למלא]` כשהערך שלה הוא בדיוק `[למלא]`). סעיף 14 שנענה, ורק השורה "איך רוצים שיחזרו אלייך" עוד `[למלא]` → ממשיכים משאלת ההמשך שלה. סעיף עם `[למלא] (נשאלה, אין תשובה עדיין)` כבר נשאל. ההערה ב-status מאשרת את זה. לא מתאים? סומכים על brief.md.
  - לומר במשפט אחד: "עצרנו אחרי <נושא>. ממשיכים מ<נושא הבא>." ולשאול רק אותה. לא חוזרים על מה שכבר נענה.
  - כל 15 הסעיפים כבר נענו → לפי ההערה: הקול (ה), או הסיכום (ו).

## ה. הראיון

לפי brief-questions.md, בסדר שם. שאלה אחת בכל הודעה, בתבנית ההודעה שם.

- **אחרי כל תשובה:** לכתוב אותה מיד לסעיף שלה ב-brief.md (וציטוטים ל-customer-words.md, בלי שמות ומספרים). ככה שיחה שנעצרה ממשיכה מאותו מקום.
- **אחרי כל 3 תשובות בערך:** `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' brief doing 'ראיון: נענו <N> מתוך 15. הבאה: <מספר> (<נושא>)'`. שאלה שדילגנו עליה כי התשובה כבר ידועה נספרת כשאלה שנענתה.
- בעל העסק ענה על כמה שאלות בהודעה אחת → לוקחים הכול, כותבים כל תשובה לסעיף שלה, ושואלים את הבאה שאין לה תשובה.
- **שאלה 14 כוללת גם "איך רוצים שיחזרו אלייך"** (בטלפון או וואטסאפ, במייל, או בשניהם). ממנה נקבעים השדות בטופס בשלב העיצוב. הערוץ כבר נאמר בתשובה ל-14 → כותבים אותו בשורה שלו בלי לשאול. לא נאמר → שאלת המשך אחת, לפי brief-questions.md › 14. היא לא נספרת כשאלה נוספת מתוך ה-15.
- בעל העסק רוצה לעצור באמצע → לשמור הערה, ולומר: "שמרתי. כשחוזרים, מקלידים `/page-brief` וממשיכים מכאן."

## ו. הקול

1. `brand/voice.md` עדיין מכיל `[למלא]` → קודם הערה: `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' brief doing 'ראיון הושלם. עכשיו: הקול'`, ואז לפי voice-profile.md.
2. אין בו `[למלא]` → שורה אחת שהקול כבר שמור, וממשיכים.

## ז. סיכום ואישור

1. למלא ב-brief.md את "בקצרה" ואת "מה עוד חסר" (לפי "איך כותבים ל-brief.md").
2. `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' brief doing 'ממתין לאישור הסיכום'`.
3. להראות:
   - את הטבלה "בקצרה" כמו שהיא בקובץ.
   - כמה ציטוטים נשמרו ב-customer-words.md, ושהשמות והמספרים נמחקו.
   - אילו הוכחות התקבלו ב-brand/proof.
   - מה עוד חסר (הרשימה מ"מה עוד חסר"). מה שחסר יופיע בקופי כ-`[למלא]`, ואפשר להשלים אחר כך.
4. לשאול: "מאשרים, או משנים משהו?" לא ממשיכים בלי אישור. שינוי → לתקן בקובץ, ולהראות שוב רק את מה שהשתנה.

## ח. שמירה ומעבר הלאה

1. לקרוא שוב את customer-words.md ולוודא שלא נשארו שמות, מספרי טלפון או מיילים. נשאר → למחוק.
2. לעדכן את CLAUDE.md לפי "אחרי הראיון: עדכון CLAUDE.md" ב-brief-questions.md.
3. `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' brief done 'האפיון אושר: <N> ציטוטים, <M> הוכחות. חסר: <מה, או: כלום>'`.
4. לסיים: "האפיון מוכן ושמור. הפקודה הבאה: `/page-copy`."
