# שלב 0 — הכנה

קודם לקרוא את החוקה ולעבוד לפיה: `<Base directory של הסקיל הזה>/../../references/stage-contract.md`.

השלב הזה שונה מהשאר בדבר אחד: הוא זה שיוצר את המצב, אז צעדים 1–2 של החוקה נעשים כאן אחרת — בסעיפים א עד ג למטה.

## נתיבים ושמות בפקודות

- `$SCRIPTS` = `<Base directory של הסקיל הזה>/../../scripts` (התיקייה). זה **קיצור בלבד**, לא משתנה של הטרמינל. משתנים לא עוברים מפקודה לפקודה, אז בכל פקודה כותבים את הנתיב המלא, למשל: `node '<Base directory של הסקיל הזה>/../../scripts/scaffold.mjs' …`.
- כל נתיב, שם או הערה בפקודה עוטפים בגרש בודד: `'דנה בע"מ'`.
- נתיב או שם שיש בו גרש (') — לכתוב אותו כ-`'\''`. למשל `צ'יפס` נכתב `'צ'\''יפס'`.

## איך פונים למשתתף

עד שיודעים — מדברים ברבים ("תנו", "כתבו"). אחרי שהמשתתף ענה, או אם זה כבר כתוב בשורה "פנייה לבעל העסק" ב-CLAUDE.md — פונים לפי זה.

## הודעת "פותחים מחדש"

כשצריך לפתוח את קלוד בתיקיית העסק, לומר בדיוק כך, עם הנתיב המלא:

> **עכשיו סוגרים את קלוד ופותחים אותו מחדש בתוך תיקיית העסק:** `<נתיב מלא>`
>
> בטרמינל במק: `cd '<נתיב מלא>' && claude`
>
> בטרמינל בווינדוס (PowerShell): `cd '<נתיב מלא>'; claude`
>
> באפליקציה: כשפותחים שיחה חדשה, בוחרים את התיקייה הזו.
>
> אחרי שנפתח — מקלידים `/page` ונמשיך משם.

## לפני הכול: Node

כל הפקודות של הסיסטם רצות על Node, וגם האתר נבנה איתו. בלי Node נכון, הפקודה הראשונה נכשלת, או שהבעיה מתגלה רק בשלב העיצוב, אחרי שעות של עבודה. לכן בודקים קודם:

`node -v`

- **מחזיר `v22.12` ומעלה** (למשל `v22.14.0`, `v24.1.0`) → ממשיכים ל-א.
- **הפקודה לא נמצאה** ("command not found", "not recognized"), **או גרסה ישנה יותר** (`v18…`, `v20…`, `v22.11` ומטה) → עוצרים, ואומרים בדיוק את זה:

  > כדי שהסיסטם יעבוד, צריך במחשב תוכנה בשם Node, בגרסה 22.12 ומעלה. מורידים את הגרסה שמסומנת LTS מ-https://nodejs.org ומתקינים כמו כל תוכנה. אחרי ההתקנה סוגרים את קלוד, פותחים אותו מחדש, ומקלידים `/page-start` שוב.

  לא ממשיכים לסעיפים הבאים, ולא מתקינים את Node בעצמנו.

## א. איפה אנחנו

1. לחפש תיקיית עסק, בתיקייה הנוכחית או מעליה: `node '$SCRIPTS/scaffold.mjs' find-root '<התיקייה הנוכחית>'`.
2. **נמצאה** (הפלט הוא נתיב) → זו תיקיית העסק, גם אם היא מעל התיקייה הנוכחית. שם העסק: מהשורה `- שם העסק:` ב-CLAUDE.md שלה, ואם אין שורה כזו — מהכותרת הראשונה שמתחילה ב-`# `. לומר "מצאתי את התיקייה של <שם העסק>: <הנתיב>" ולדלג ל-ג. **אף פעם לא ליצור תיקיית עסק חדשה בתוכה.**
   - בשורה `- פנייה לבעל העסק:` ב-CLAUDE.md עדיין כתוב `[זכר / נקבה / רבים]` (או שהיא ריקה)? כנראה שיחה קודמת נקטעה לפני שענו. לשאול עכשיו, בהודעה נפרדת, את השאלה מסעיף 5, ולכתוב את התשובה באותה שורה.
3. **לא נמצאה** ("לא נמצאה תיקיית עסק") → לחפש רמה אחת מתחת: `node '$SCRIPTS/scaffold.mjs' find-below '<התיקייה הנוכחית>'`. הפלט הוא רשימה של נתיבים (אולי ריקה).
   - **נמצאה אחת** → לומר "מצאתי את תיקיית העסק ב-<הנתיב>", לתת את הודעת "פותחים מחדש" עם הנתיב הזה, ולהוסיף: "אחרי שנפתח שם — מקלידים `/page-start` שוב לדף חדש, או `/page` להמשיך." ולעצור.
   - **נמצאו כמה** → להראות את הרשימה ולשאול באיזו עובדים. אחרי התשובה — כמו "נמצאה אחת".
   - **אסור ליצור עסק חדש כשנמצאה תיקיית עסק מתחת**, אלא אם המשתתף אומר במפורש שזה עסק אחר. רק אז ממשיכים לסעיף 4.
4. **אין עדיין סיסטם** → הסיסטם תמיד יושב בתיקייה בשם **`סיסטם דפי נחיתה`**, בתוך **התיקייה הראשית של העסק** ("המוח של העסק": התיקייה שבה יושב כל מה שעושים בעסק, עם CLAUDE.md של כללי העסק, ולצידו נושאים אחרים כמו פגישות). קודם מוצאים את התיקייה הראשית:
   - **התיקייה הנוכחית נקראת `סיסטם דפי נחיתה` והיא ריקה** → התיקייה שמעליה היא הראשית (אלא אם זו הבית, שולחן העבודה, מסמכים או הורדות: אז כמו בסעיף האחרון). בונים כאן.
   - **בתיקייה הנוכחית יש CLAUDE.md בלי הסימן של הסיסטם, או שבעל העסק אומר שזו התיקייה הראשית של העסק** → היא הראשית. מציעים: "אבנה כאן תיקייה בשם סיסטם דפי נחיתה, ובתוכה את כל הסיסטם", ומחכים לאישור.
   - **אחרת** (הבית, שולחן העבודה, מסמכים, הורדות, או לא ברור) → שאלה אחת: "יש לכם כבר תיקייה ראשית לעסק, שבה יושב כל מה שאתם עושים בעסק? אם כן, תגררו אותה לכאן. אם לא, אבנה אחת."
     - יש → בונים בתוכה `סיסטם דפי נחיתה`, אחרי אישור.
     - אין → שם העסק (שאלה אחת), ואז מציעים: "אבנה ב-<התיקייה הנוכחית> תיקייה ראשית בשם <שם העסק>, עם קובץ הכללים של העסק, ובתוכה את סיסטם דפי נחיתה." אחרי אישור: יוצרים את התיקייה הראשית, וכותבים בה `CLAUDE.md` מהתבנית `<Base directory של הסקיל הזה>/../../templates/business-root.md` (שם העסק במקום `{{businessName}}`).
   - **CLAUDE.md ראשי שכבר קיים לא דורסים.** אם אין בו שורה על `סיסטם דפי נחיתה/` תחת הנושאים, מוסיפים שורה אחת בסוף הקובץ: `- סיסטם דפי נחיתה/ — דפי הנחיתה של העסק`, ואומרים את זה במשפט.
   - **שם העסק:** מה-CLAUDE.md הראשי, אם כתוב שם. לא שואלים שוב. אחרת שואלים.
   - ליצור את הסיסטם: `node '$SCRIPTS/scaffold.mjs' business '<התיקייה הראשית>/סיסטם דפי נחיתה' '<שם העסק>'`. השם של התיקייה תמיד `סיסטם דפי נחיתה`, ושם העסק נשמר ב-CLAUDE.md.
   - אם כבר היה CLAUDE.md בתיקיית הסיסטם — הסקריפט משאיר את מה שכתוב בו ומוסיף את החלקים של הסיסטם מתחת. לומר את זה למשתתף במשפט אחד.
   - הסיסטם נוצר בתיקייה אחרת מהתיקייה הנוכחית → בסוף השלב, הודעת "פותחים מחדש" על `<התיקייה הראשית>/סיסטם דפי נחיתה`.
5. תיקיית העסק נוצרה עכשיו (או נמצאה, והפנייה עוד לא מולאה, ראו 2) — אם הפנייה כתובה ב-CLAUDE.md הראשי, מעתיקים משם. אחרת, עוד שאלה, בהודעה נפרדת: "איך לפנות אליכם — בלשון זכר, נקבה או רבים?". לכתוב את התשובה ב-CLAUDE.md של העסק, בשורה `- פנייה לבעל העסק:`.

## ב. להסביר את הארכיטקטורה (פעם ראשונה בלבד)

אם תיקיית העסק נוצרה עכשיו — להראות את העץ, מהתיקייה הראשית של העסק, עם השמות כמו שהם בדיסק, ולהסביר בארבע שורות:

- **התיקייה הראשית של העסק** — המוח של העסק. כאן יושב כל מה שעושים בעסק, כל נושא בתיקייה משלו (למשל פגישות), ו-`סיסטם דפי נחיתה` הוא אחד מהם.
- **CLAUDE.md** — בתיקייה הראשית: הכללים של כל העסק. בתוך `סיסטם דפי נחיתה`: הזיכרון של הסיסטם. כל פקודה קוראת את שניהם.
- **brand/ ו-legal/** — ממלאים פעם אחת, משמשים את כל הדפים.
- **landing-pages/** — תיקייה לכל דף, עם מקום קבוע לכל שלב.

ומיד אחרי, פעם אחת בלבד, משפט על עלויות: ההודעה מ"ב-`/page-start`, פעם אחת" ב-`<Base directory של הסקיל הזה>/../../references/costs.md`, כמו שהיא, בפנייה הנכונה. לא עוצרים בגללה.

## ג. דף חדש

1. **קודם: יש דף שההכנה שלו לא הסתיימה?** `node '$SCRIPTS/status.mjs' list '<תיקיית העסק>'`. דף שה-`next` שלו הוא `start` (שיחה קודמת נקטעה אחרי שהתיקייה נוצרה, למשל באמצע התקנת הכלים) → לא יוצרים דף חדש. לומר: "מצאתי את הדף <pageName> שהתחלנו ולא סיימנו את ההכנה שלו. ממשיכים איתו." ומדלגים ל-ד (כלים) עם התיקייה שלו. יש כמה כאלה → לשאול עם איזה ממשיכים. דף חדש נוצר רק כשאין דף כזה, או כשבעל העסק ביקש במפורש דף נוסף.
2. שם הדף: מהארגומנט אם נשלח. אחרת לשאול: "על מה הדף? תנו לו שם קצר" (דוגמה: "סדנת גיוס", "מדריך חינמי").
3. ליצור: `node '$SCRIPTS/scaffold.mjs' page '<תיקיית העסק>' '<שם הדף>'`. הפלט הוא הנתיב של תיקיית הדף.
4. להראות את התיקיות שנוצרו ומה נכנס לכל אחת, במשפט אחד לכל תיקייה.

## ד. כלים

קודם הגרסה של קלוד: `claude --version`. הפלאגין נבדק מול **2.1.300** (1.11.26).

- הפקודה עובדת והמספר קטן מ-2.1.300 (משווים מספר אחרי מספר: 2.0.x קטן מ-2.1.x, ו-2.1.99 קטן מ-2.1.300) → להציע `claude update` (המשתתף מאשר), ולומר שאחרי העדכון סוגרים ופותחים את קלוד.
- 2.1.300 ומעלה → מעודכן. לא אומרים כלום.
- הפקודה לא נמצאה ("command not found", קורה באפליקציה) → לא מציעים `claude update`. משפט אחד: "באפליקציה, קלוד מתעדכן לבד. אם מופיעה הודעה על גרסה חדשה, כדאי לאשר אותה ולפתוח מחדש."

אחר כך לבדוק מה כבר מותקן ולהתקין רק את מה שחסר. לכל כלי — משפט אחד למה הוא שם:

- התקנה שנכשלה: לא לעצור. לרשום ולהמשיך. השלבים הבאים יודעים לעבוד בלעדיה ויגידו מה לא נבדק.

## ה. סיום

1. `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' start done 'התיקייה מוכנה. הותקנו: <שמות הכלים שהותקנו, או: כלום>. דולג: <מה דולג ולמה, או: כלום>'`.
2. **תיקיית העסק נמצאת מתחת לתיקייה שבה קלוד נפתח, או במקום אחר** (לא אותה תיקייה ולא תיקייה מעליה) → תמיד, גם אם לא הותקן כלום, לתת את הודעת "פותחים מחדש". קלוד קורא את ה-CLAUDE.md של העסק רק כשהוא נפתח בתוכה או בתיקייה שבתוכה.
3. **קלוד נפתח בתיקיית העסק או בתיקייה שבתוכה, והותקן משהו** → לתת את הודעת "פותחים מחדש". קלוד טוען כלים חדשים רק כשהוא עולה.
4. **קלוד נפתח בתיקיית העסק או בתיקייה שבתוכה, ולא הותקן כלום** → לומר: "הכול מוכן. הפקודה הבאה: `/page-brief`".
