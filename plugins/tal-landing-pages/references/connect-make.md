# Make: התרחיש שמקבל כל ליד

הקובץ הזה משמש את `/page-connect` (שלבים 7ב–7ד). הוא אומר לקלוד איך לבנות עם בעל העסק את התרחיש ב-Make, או לבנות אותו בעצמו אם יש חיבור.

## העיקרון

הטופס שולח לנקודה אחת באתר (`/api/lead`). משם הליד נשמר בגיבוי, ונשלח פעם אחת לכתובת אחת ב-Make (`WEBHOOK_URL`). כל השאר קורה בתוך Make: לאן הליד הולך, באיזה סדר, ומה עושים כשמשהו נופל. כך מוסיפים או מחליפים כלי בלי לגעת באתר.

```
טופס ← /api/lead ← גיבוי (Vercel Blob)
                 ← Make: Custom webhook ← Router ─┬─ רב מסר (רק מי שהסכים לדיוור)
                                                  ├─ Google Sheets
                                                  ├─ Monday / Airtable
                                                  └─ הודעה לבעל העסק
```

## מה הוובהוק מקבל

המקור: `site/TEMPLATE.md`, "מה הוובהוק מקבל". POST אחד לכל ליד, JSON שטוח, שדה לכל עמודה:

| שדה                                                                   | מה זה                                                                    |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `id`                                                                  | מזהה הליד. אותו מזהה בגיבוי (`leads/<תאריך>/<id>.json`)                  |
| `createdAt`                                                           | מתי נשלח, בזמן עולמי (UTC). בישראל זה שעתיים או שלוש יותר                |
| `name`, `email`, `phone`                                              | מה שהליד מילא. `phone` בפורמט `05...`, או ריק. `email` ריק כשאין שדה מייל בטופס (`form.email: "hidden"`) או שהוא רשות ולא מולא |
| `marketingConsent`                                                    | `true` רק אם הליד סימן בעצמו את תיבת הדיוור. רק אז הוא נכנס לרשימת דיוור |
| `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` | מאיפה הגיע (מהקישור). ריק אם אין                                         |
| `source`                                                              | `utm_source`, ואם אין: `אחר`                                             |
| `fbclid`, `fbp`, `fbc`                                                | מזהים של מטא. `fbp` ו-`fbc` רק אם הליד אישר עוגיות שיווק                 |
| `referrer`, `landingPath`, `pageUrl`                                  | מאיזה אתר הגיע, ובאיזו כתובת נחת                                         |
| `eventId`                                                             | המזהה של אירוע ה-Lead במטא                                               |

ערך בשדה חופשי שמתחיל ב-`=`, `+`, `-`, `@` מגיע עם גרש `'` בהתחלה. זה בכוונה, כדי שגיליון לא יריץ אותו כנוסחה.

## בונים את התרחיש (בלי חיבור Make לקלוד)

הוראות לבעל העסק, צעד אחרי צעד. שמות הכפתורים נבדקו מול https://apps.make.com/gateway (התיעוד של Webhooks, נוצר אצלם 3.4.25) ב-1.11.26.

### 1. הוובהוק

1. נכנסים ל-https://www.make.com ← **Scenarios** ← **Create a new scenario**.
2. לוחצים על הפלוס הגדול ← מחפשים **Webhooks** ← בוחרים **Custom webhook**.
3. ליד השדה **Webhook** לוחצים **Add** ← **Webhook name**: למשל `לידים - <שם הדף>` ← **Save**.
4. Make יוצר כתובת שמתחילה ב-`https://hook.` ומתחיל להקשיב. **מעתיקים אותה** (יש כפתור העתקה ליד הכתובת).
5. **הכתובת הזו היא סוד.** מי שיש לו אותה יכול לשלוח לידים מזויפים. לא מדביקים אותה בצ'אט, לא בקובץ ולא במייל. היא נכנסת רק ל-Vercel, בטרמינל של בעל העסק (`/page-connect` מסביר איך).
6. **לא סוגרים את המודול.** הוא מחכה לליד הראשון כדי ללמוד את המבנה.

### 2. ליד בדיקה, כדי ש-Make ילמד את המבנה

Make לא יודע אילו שדות יגיעו עד שמגיע ליד אמיתי. בלי זה, במודולים הבאים לא יופיעו השדות למיפוי.

1. אחרי ש-`WEBHOOK_URL` הוגדר ב-Vercel והאתר נפרס מחדש: שולחים ליד בדיקה מהדף החי (קלוד מסביר ב-`/page-connect`, שלב 7ב).
2. במודול של הוובהוק אמור להופיע אישור שהמבנה נקלט (בממשק הישן: **Successfully determined**. הנוסח המדויק לא אומת בתיעוד). מעכשיו השדות זמינים במודולים הבאים.
3. **שדה חדש, או ש-Make "לא ראה" את הליד:** פותחים את מודול הוובהוק ולוחצים **Redetermine data structure**. בממשק החדש של Make הכפתור נקרא **Detect new values** (ככה הוא מופיע בתיעוד העדכני). שולחים עוד ליד בדיקה.
4. הכפתור לא מופיע? הוא קיים רק במודול **Custom webhook**, לא במודולים של אפליקציות שיש להן וובהוק משלהן.

### 3. ה-Router והענפים

1. מוסיפים אחרי הוובהוק מודול **Router** (חיפוש: Router, תחת Flow Control). כל ענף יוצא ממנו בנפרד, וכישלון בענף אחד לא עוצר את השאר.
2. ענף לכל כלי שבעל העסק משתמש בו. רק מה שבאמת בשימוש.

| ענף             | המודול ב-Make                                                                    | מה ממפים                                                                                                     | שימו לב                                                                                                                                                            |
| --------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| רב מסר          | **Responder.live (רב מסר)** ← **Add a New Subscriber**. ראו `connect-mailing.md` | שם, מייל, טלפון, הרשימה הנכונה                                                                               | **פילטר על הענף:** `marketingConsent` = `true` (Boolean). בלי הפילטר, מי שלא הסכים לדיוור נכנס לרשימה, וזה נגד החוק                                                |
| Google Sheets   | **Google Sheets** ← **Add a Row**                                                | עמודה לכל שדה: `createdAt`, `name`, `email`, `phone`, `marketingConsent`, `utm_source`, `utm_campaign`, `id` | **Value input option: Raw.** כך שום ערך לא נקרא כנוסחה (מתוך TEMPLATE.md. בתיעוד של Make לא נמצא תיאור של השדה הזה ב-1.11.26, לכן אם הוא לא מופיע, לבקש צילום מסך) |
| Monday          | **monday.com** ← **Create an Item**                                              | שם הליד בשם הפריט, וכל השאר לעמודות של הלוח                                                                  | קודם יוצרים בלוח עמודות: מייל, טלפון, מקור, תאריך                                                                                                                  |
| Airtable        | **Airtable** ← **Create a Record**                                               | שדה לכל עמודה בטבלה                                                                                          | קודם יוצרים בטבלה את השדות                                                                                                                                         |
| הודעה לבעל העסק | **Email** ← **Send an Email**, או **Gmail** ← **Send an email**                  | נושא: "ליד חדש: {{name}}". בגוף: טלפון, מייל, מקור                                                           | ההודעה נשלחת לבעל העסק בלבד, לא לליד                                                                                                                               |

3. **ממפים לפי השם, לא לפי המיקום.** בכל שדה במודול לוחצים, ובוחרים מהרשימה של מודול 1 (הוובהוק) את השדה עם אותו שם.
4. **שומרים** (סמל הדיסקט למטה) ונותנים לתרחיש שם: `לידים - <שם הדף>`.

### 4. הדלקה

- למטה משמאל, המתג **Scheduling** / **ON**. בוובהוק התרחיש רץ מיד כשמגיע ליד, לא כל רבע שעה.
- **תרחיש כבוי:** Make עדיין מקבל את הליד ושומר אותו בתור של הוובהוק (לפי https://help.make.com/webhooks, נוצר אצלם 3.2.25), ועונה לאתר "Accepted". האתר חושב שהכול עבר. לכן אחרי ההדלקה תמיד שולחים ליד בדיקה ובודקים ב-History.
- וובהוק שלא מחובר לשום תרחיש יותר מ-5 ימים מושבת, ו-Make מחזיר שגיאה (410). אז הליד נשמר רק בגיבוי, וההתראה (אם הוגדרה) יוצאת.

## איך רואים שהליד עבר: History

נבדק מול https://help.make.com/scenario-history (נוצר אצלם 3.2.25) ב-1.11.26.

1. **Scenarios** ← לוחצים על התרחיש ← לשונית **History**.
2. כל ריצה מופיעה עם מצב: **Success**, **Warning** או **Error**, ושעה.
3. **Details** בצד של הריצה ← לוחצים על העיגול הקטן עם המספר שמעל כל מודול ← רואים מה יצא ממנו (Output). במודול 1 רואים את כל השדות שהגיעו מהאתר.
4. **ההוכחה ל-7ב:** בריצה של ליד הבדיקה, ב-Output של מודול 1, מופיעים כל השדות מהטבלה למעלה, ו-`utm_source` הוא `test`. צילום מסך של המסך הזה.

**Error בענף אחד:** לוחצים עליו ורואים את ההודעה. הכי נפוץ: החיבור לכלי פג (צריך להתחבר מחדש), שדה חובה לא מופה, או עמודה שנמחקה בגיליון.

## כמה זה עולה בחבילה החינמית

נבדק מול https://www.make.com/en/pricing ו-https://help.make.com/credits ב-1.11.26.

- Make סופר **קרדיטים** (פעם זה נקרא "פעולות", operations). רוב המודולים: קרדיט אחד בכל פעם שהם רצים. **Router לא עולה קרדיט.** לפי עמוד המחירים, גם "קריאת מידע מוובהוק" צורכת קרדיט.
- **החבילה החינמית: 1,000 קרדיטים בחודש** (מעמוד המחירים).
- **ליד אחד בתרחיש עם ארבעה ענפים** (רב מסר, Sheets, Monday, הודעה): הוובהוק (1) + 4 מודולים = **בערך 5 קרדיטים**. ליד שלא הסכים לדיוור נעצר בפילטר של רב מסר, אז 4.
- **כלומר: בערך 200 לידים בחודש בחבילה החינמית.** כל ענף שמוסיפים מוריד את המספר. ליד בדיקה עולה כמו ליד אמיתי.
- תרחיש שרץ לפי לוח זמנים (כל 15 דקות, למשל) שורף קרדיטים גם כשאין לידים. בוובהוק זה לא קורה: הוא רץ רק כשיש ליד.
- **מספר התרחישים הפעילים בחבילה החינמית: 2**, לפי מקורות משניים (למשל https://www.jetadmin.io/blog/make-pricing/). **לא אומת בעמוד הרשמי** ב-1.11.26. אם זה נכון, תרחיש הלידים ותרחיש ההתראה כבר תופסים את שניהם.
- מה קורה כשהקרדיטים נגמרים באמצע החודש: לא כתוב בעמודים שנבדקו. **לא אומת.** לכן ההתראה (`ALERT_WEBHOOK_URL`) והגיבוי חשובים, ולכן כדאי לבדוק פעם בחודש ב-Make כמה נשאר (בתפריט: Organization ← Subscription / Usage).

## כשיש חיבור Make לקלוד (MCP)

לפעמים לבעל העסק כבר יש בקלוד חיבור ל-Make. אז קלוד יכול לבנות את התרחיש בעצמו, במקום להסביר לחיצות.

**איך בודקים אם יש חיבור:**

1. `ToolSearch` עם `+scenarios create`, ואחר כך עם `hooks create`. מחפשים כלים שהשם שלהם נגמר ב-`scenarios_create`, `hooks_create`, `scenarios_activate`, `scenarios_run`, `executions_list`.
2. נמצאו → לבדוק שהחיבור עובד ושייך לבעל העסק: קריאה לכלי `users_me` (או `organizations_list`), ולשאול: "אני מחובר ל-Make בתור <שם / ארגון>. זה החשבון שלכם?" לא → לא נוגעים, ועוברים להוראות הלחיצה.
3. לא נמצאו, או שהכלים דורשים התחברות → הוראות הלחיצה למעלה. לא מחברים כלי חדש לקלוד בלי אישור מפורש של בעל העסק, וזה לא חלק מהשלב הזה.

**מה קלוד בונה בעצמו:**

1. וובהוק (`hooks_create`, מסוג Custom webhook) ותרחיש (`scenarios_create`) עם אותם מודולים כמו בטבלה, **כבוי**. את המודולים והשדות בודקים עם כלי התיעוד של החיבור (`app-modules_list`, `app_documentation_get`, `validate_blueprint_schema`) ולא מנחשים.
2. החיבורים לכלים עצמם (רב מסר, Google, Monday) הם של בעל העסק. אם חסר חיבור (`connections_list`), בעל העסק יוצר אותו ב-Make בעצמו (Connections ← Add), כי זו התחברות לחשבון שלו.
3. **כתובת הוובהוק שהכלי מחזיר לא נכתבת בצ'אט, בקובץ או בפקודה.** בעל העסק מעתיק אותה בעצמו מתוך Make (פותחים את התרחיש ← מודול הוובהוק ← כפתור ההעתקה) ומדביק בטרמינל שלו.
4. **מראים לפני שמדליקים:** טבלה של המודולים, הפילטר על רב מסר, ואיזה שדה הולך לאן. ושאלה: "להדליק את התרחיש?"
5. **מדליקים (`scenarios_activate`) רק אחרי "כן" מפורש** באותו רגע. אחרי ההדלקה: ליד בדיקה, ואז `executions_list` כדי לראות שהריצה הצליחה, כולל כל ענף. "ההדלקה הצליחה" זה לא "התרחיש עובד": התרחיש עובד רק כשיש ריצה עם Success.
6. לא מריצים את התרחיש על לידים אמיתיים ולא שולחים דרכו הודעות לרשימה. ריצה רק עם ליד הבדיקה של בעל העסק.

## תרחיש ההתראה (רשות, מומלץ)

מתוך TEMPLATE.md, "ליד שלא הגיע ל-Make":

1. תרחיש נפרד: **Custom webhook** ← **Email / Gmail: Send an email** לבעל העסק.
2. בנושא: "ליד לא הגיע ל-Make". בגוף: `id`, `createdAt`, `webhookStatus`, `message`. אין שם או טלפון בהתראה, וזה בכוונה.
3. הכתובת של הוובהוק הזה נכנסת ל-Vercel כ-`ALERT_WEBHOOK_URL`.
4. **חולשה שכדאי לדעת:** אם Make עצמו לא זמין או שהקרדיטים נגמרו, גם ההתראה (שעוברת דרך Make) לא תגיע. הגיבוי ב-Vercel ממשיך לשמור. לכן פעם בשבוע מסתכלים ב-History שיש ריצות.
