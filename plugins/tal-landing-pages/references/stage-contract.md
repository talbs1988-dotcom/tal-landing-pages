# החוקה של סקיל שלב

כל סקיל של שלב (`/page-brief` עד `/page-connect`) עובד לפי ששת הצעדים האלה, באותו סדר. ככה המשתתף לומד את הקצב פעם אחת, וקלוד לא מדלג.

## נתיבים ושמות בפקודות

- סקיל של שלב מוצא את הקבצים של הפלאגין מה-Base directory שלו, כמו `/page-start`:
  - הסקריפטים: `<Base directory של הסקיל>/../../scripts/`
  - החוקה הזו: `<Base directory של הסקיל>/../../references/stage-contract.md`
- `$SCRIPTS` = `<Base directory של הסקיל>/../../scripts` (התיקייה). זה **קיצור בלבד**, לא משתנה של הטרמינל. משתנים לא עוברים מפקודה לפקודה, אז בכל פקודה כותבים את הנתיב המלא.
- כל נתיב, שם או הערה בפקודה עוטפים בגרש בודד: `'דנה בע"מ'`.
- נתיב או שם שיש בו גרש (') — לכתוב אותו כ-`'\''`. למשל `צ'יפס` נכתב `'צ'\''יפס'`.

## 1. לקרוא מצב

- למצוא את תיקיית העסק: `node '$SCRIPTS/scaffold.mjs' find-root '<התיקייה הנוכחית>'`. תיקיית עסק היא תיקייה שה-CLAUDE.md שלה מכיל את השורה `<!-- tal-landing-pages:business -->`. `find-root` בודק את זה בתיקייה הנוכחית ועולה למעלה עד שהוא מוצא, ומדפיס את הנתיב.
- לא נמצאה ("לא נמצאה תיקיית עסק")? לחפש רמה אחת מתחת: `node '$SCRIPTS/scaffold.mjs' find-below '<התיקייה הנוכחית>'` (רשימה של נתיבים).
  - נמצאה אחת, או כמה ונבחרה אחת → לומר "מצאתי את תיקיית העסק ב-<הנתיב>", לתת את הודעת "פותחים מחדש" כמו ב-`/page-start` (נתיב מלא, `cd '<נתיב מלא>' && claude` במק, `cd '<נתיב מלא>'; claude` בווינדוס ב-PowerShell, ושורה לאפליקציה), ולעצור.
  - הרשימה ריקה → לעצור ולומר: "אנחנו לא בתיקיית עסק. מריצים קודם `/page-start`".
- למצוא את הדף: `node '$SCRIPTS/status.mjs' list '<תיקיית העסק>'`. תיקיות בלי קובץ מצב לא מופיעות ולא נחשבות. דף שיש לו `error` — להציג כ"דף עם קובץ מצב פגום" ולא לעבוד עליו.
  - אין דפים → לעצור ולומר: "אין עדיין דף. מקלידים `/page-start`."
  - התיקייה הנוכחית בתוך אחד הדפים (`landing-pages/NN-x/...`) — הוא.
  - דף אחד — הוא.
  - כמה דפים — להציג את הרשימה ולשאול על איזה עובדים.
- לקרוא: ה-`CLAUDE.md` של התיקייה הראשית של העסק, מעל `סיסטם דפי נחיתה` (המוח של העסק: מי העסק, למי, איך מדברים), ואת `CLAUDE.md` של הסיסטם (כולל "החלטות"), `brand/brand.md`, `brand/voice.md`, `legal/business.md`, ואת הפלט של **כל** השלבים הקודמים של הדף (`1-brief/brief.md`, `2-copy/copy.md`, `3-design/design.md`, `5-connect/connections.md`, מה שקיים). בדף שני והלאה, גם את ההחלטות שכבר נרשמו מדפים קודמים של העסק.
- **קודם קוראים, אחר כך שואלים.** לפני כל שאלה בודקים אם התשובה כבר כתובה באחד הקבצים:
  - כתובה → לא שואלים. אומרים במשפט מה ידוע ומאיפה, וממשיכים. למשל: "לפי האפיון, זה דף הרשמה חינמי למדריך, עם מחיר 0."
  - כתובה וסותרת את מה שבעל העסק כתב עכשיו → שואלים פעם אחת מה נכון, ומעדכנים את הקובץ.
  - חסרה, ריקה או `[למלא]` → שואלים, שאלה אחת בכל פעם.
  - הפרומפט מהמדריך קצר בכוונה. מה שלא כתוב בו, מחפשים בקבצים לפני ששואלים.

## 2. לבדוק תנאי כניסה

- `node '$SCRIPTS/status.mjs' show '<תיקיית הדף>'`.
- השלב הקודם לא אושר? לעצור, להסביר במשפט אחד למה הסדר חשוב, ולתת את הפקודה של השלב החסר.
- לסמן את השלב "בעבודה": `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' <id> doing`. בלי הערה — ההערה הקודמת של השלב נשמרת.

## 3. לבדוק ולהתקין כלים

- כל סקיל מפרט אילו כלים הוא צריך. כלי חסר: להסביר במשפט אחד מה הוא נותן, להריץ את ההתקנה (המשתתף מאשר), ולומר אם צריך לסגור ולפתוח את קלוד. את שורת ההתקנה המדויקת לוקחים מהטבלה ב-`/page-start`, ד. לא שולחים את המשתתף להריץ `/page-start` בשביל כלי: `/page-start` מיועד לדף חדש.
- כלי שאי אפשר להתקין: לא לעצור את כל השלב. לרשום ב-status מה דולג ולמה.

## 4. להנחות ולשאול

- **שאלה אחת בכל הודעה.** עם דוגמה קצרה לתשובה טובה.
- כשצריך מהמשתתף קובץ, לינק או צילום מסך — להסביר בדיוק מאיפה מביאים ולאיזו תיקייה זורקים.
- שפה פשוטה, בלי מונחים טכניים. אם אין ברירה — להסביר במילים של בעל עסק.
- לפנות למשתתף לפי השורה "פנייה לבעל העסק" ב-CLAUDE.md (זכר / נקבה / רבים). לא מולאה — ברבים. השורה "פנייה לקהל" היא על הטקסט של הדף, לא על השיחה.

## 5. לעבוד, להראות, לעצור לאישור

- להראות את התוצאה (קובץ, תצוגה, טבלה), לא רק לתאר אותה.
- לשאול: "מאשרים, או משנים משהו?" ולא להמשיך בלי אישור.
- **בכל נקודת אישור בתוך השלב** — לעדכן את ההערה, כדי ש-`/page` ידע מאיפה להמשיך: `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' <id> doing '<איפה עצרנו, למשל: סקשן 3 מתוך 7 אושר>'`.
- **"נראה עובד" זה לא "עובד".** כל מה שאפשר לבדוק בפועל — בודקים, ומספרים מה בדקנו.
- לפתוח מחדש שלב שכבר אושר (להחזיר אותו ל-`doing`) מותר, בכוונה. למשל: רוצים לשנות את הקופי אחרי שהעיצוב התחיל. תמיד עם הערה חדשה, כדי שהסיכום הישן של "אושר" לא ייראה כמו נקודת המשך: `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' <id> doing 'נפתח מחדש: <למה>'`. לומר למשתתף אילו שלבים אחריו כדאי לעבור שוב.

## 6. לשמור ולהעביר הלאה

- לכתוב את הפלט לתיקיית השלב.
- החלטה שתשפיע על דפים הבאים (צבע, טון, פרטי עסק) — לרשום גם ב-`CLAUDE.md` תחת "החלטות", עם תאריך.
- `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' <id> done '<משפט אחד מה נעשה>'`.
- לסיים במשפט אחד: מה נעשה, ומה הפקודה הבאה.

## אסור תמיד

- להמציא מספרים, המלצות, לקוחות, פרטי עסק או הבטחות. חסר → `[למלא]`, ונאסף לרשימה.
- לגעת בכסף, לשלוח הודעות או לפרסם משהו בלי אישור מפורש באותו רגע.
- לכתוב מפתחות, סיסמאות או טוקנים בתוך קבצים.
