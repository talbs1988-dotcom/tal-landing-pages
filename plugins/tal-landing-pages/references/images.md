# תמונות בדף

הקובץ הזה הוא בשביל קלוד, בשלב העיצוב (תת-שלב 3ג). הוא מסביר איפה התמונות יושבות, איך בוחרים, מעבדים, מטשטשים וכותבים להן תיאור, ומה עושים כשאין תמונה.

## איפה כל תמונה יושבת

| תיקייה                                   | מה יש בה                                                         | מי שם שם                        |
| ---------------------------------------- | ---------------------------------------------------------------- | ------------------------------- |
| `landing-pages/NN-x/images-inbox/`       | תמונות של הדף הזה, בלי סדר ובלי שמות מיוחדים                     | בעל העסק                        |
| `brand/photos/`                          | תמונות של בעל העסק והעסק, משותפות לכל הדפים                      | בעל העסק                        |
| `brand/photos/ai/`                       | תמונות שנוצרו ב-Higgsfield (ראו `higgsfield.md`)                 | קלוד, אחרי אישור                |
| `brand/proof/`                           | המלצות, צילומי מסך של וואטסאפ וביקורות, כתבות, לוגואים של לקוחות | בעל העסק                        |
| `landing-pages/NN-x/site/public/assets/` | רק תמונות מעובדות שנכנסות לדף                                    | קלוד בלבד, דרך `npm run images` |

המקורות נשארים איפה שהם. לא מוחקים ולא משנים אותם. מה שעולה לאוויר זה רק `public/assets/`, ולכן מקור עם מספר טלפון או פרצוף של לקוח אף פעם לא מועתק לשם ישירות. כל תמונה נכנסת לדף רק דרך הסקריפט.

## איך מסתכלים על התמונות

1. קוראים את `2-copy/images-list.md`. שם כתוב איזו תמונה צריך בכל סקשן, באיזה כיוון, ומה היא צריכה להראות.
2. רשימה של כל הקבצים ב-`images-inbox/`, ב-`brand/photos/` וב-`brand/proof/`.
3. פותחים כל תמונה עם Read. לא בוחרים לפי שם קובץ.
4. לכל תמונה כותבים לבעל העסק שורה אחת: מה רואים בה, ואם היא מתאימה. למשל: "IMG_2041: דנה מדגימה תרגיל בסטודיו, אור טוב, אופקית. מתאימה להירו".
5. בוחרים תמונה לכל שורה ב-images-list ומסבירים למה, במשפט: "בחרתי את IMG_2041 להירו כי רואים את הפנים שלך ואת הסטודיו ביחד, והיא אופקית כמו שצריך".
6. תמונה מטושטשת, חשוכה, עם רקע עמוס או בכיוון הלא נכון: אומרים את זה בפשטות ומציעים חלופה (תמונה אחרת, הנחיות צילום, גרפיקה, מאגר חינמי).
7. מחכים לאישור על הבחירה לפני העיבוד.

## עיבוד: `npm run images`

מריצים מתוך תיקיית `site/` של הדף. אחרי `npm run images` חייב לבוא `--`, אחרת npm בולע את הדגלים.

```bash
# קודם המידות של המקור (כמו שהתמונה נראית ישר, אחרי סיבוב)
npm run images -- '../images-inbox/IMG_2041.jpg' --info

# עיבוד
npm run images -- '../images-inbox/IMG_2041.jpg' herodana --role hero
npm run images -- '../../../brand/proof/review-1.png' review-michal --role inline --blur 40,20,380,70
```

| role     | מתי                                                | רוחב מקסימלי | תקרת משקל |
| -------- | -------------------------------------------------- | ------------ | --------- |
| `hero`   | התמונה הגדולה בראש הדף                             | 2000         | 200KB     |
| `inline` | תמונות בתוך הדף, צילומי מסך של המלצות              | 1200         | 100KB     |
| `thumb`  | תמונות קטנות: לוגואים של לקוחות, תמונת פרופיל קטנה | 600          | 50KB      |

מה הסקריפט עושה: מסובב לפי ה-EXIF (צילומי טלפון), מוחק את כל ה-metadata כולל מיקום GPS, מטשטש (`--blur`), חותך (`--crop x,y,w,h`), מקטין לרוחב של ה-role, ודוחס ל-webp. האיכות יורדת בצעדים עד שהקובץ מתחת לתקרה, ואם גם באיכות 40 הוא כבד מדי, הרוחב קטן. בסוף הוא מדפיס שורה כמו `נשמר public/assets/herodana.webp · 2000×1333 פיקסלים · 184KB · איכות 70`. את הרוחב והגובה משם מעתיקים לקוד.

- שם היעד: אותיות לטיניות קטנות וספרות בלבד, **בלי מקפים** (`herodana`, `reviewmichal2`). אותו שם משמש גם למפתח ה-alt, ומפתח עם מקף נכשל בבדיקות של האתר. לתמונת הפתיחה (`--role hero`) השם מתחיל ב-`hero`, כי `/page-check` מזהה לפיו את התקרה של 200KB.
- כבר יש קובץ בשם הזה? הסקריפט עוצר. מחליפים בכוונה עם `--force`.
- קובץ HEIC מאייפון לא נפתח. מבקשים מבעל העסק לשלוח כ-JPG, או לשנות בהגדרות המצלמה של האייפון את הפורמט מ-High Efficiency ל-Most Compatible.
- אם הרוחב יצא קטן בהרבה מהתקרה (למשל הירו ברוחב 900), התמונה עמוסה מדי בפרטים. עדיף לחתוך אותה צמוד יותר, או לבחור תמונה אחרת.

## מתי חובה לטשטש

בכל צילום מסך של וואטסאפ, הודעה, מייל או ביקורת. בלי יוצא מן הכלל, גם אם בעל העסק אומר "זה בסדר, זה לקוח שלי". מטשטשים:

- מספרי טלפון, מיילים, כתובות, מספרי הזמנה וחשבוניות.
- שמות של לקוחות שלא אישרו שהשם שלהם יופיע. אישור נרשם ב-`2-copy/images-list.md` ליד התמונה ("מיכל אישרה בוואטסאפ ב-3.11"). אין אישור רשום → מטשטשים.
- תמונות פרופיל ופרצופים של אנשים שהם לא בעל העסק.
- שעה ותאריך, רק אם הם חושפים משהו (למשל לוח זמנים של לקוח).

הטקסט של ההמלצה עצמה נשאר קריא. הוא הסיבה שהתמונה בדף.

**חיתוך במקום טשטוש:** כשכל מה שרגיש נמצא מחוץ לבועה של ההמלצה (שם ותמונת פרופיל בראש המסך, מספר טלפון), אפשר לחתוך עם `--crop` רק את הבועה, והמידע הרגיש לא נכנס לתמונה בכלל. אחרי העיבוד פותחים את התוצאה ובודקים בעיניים שלא נשאר שם, מספר או פנים. רגיש בתוך הבועה עצמה → טשטוש, גם אם חתכנו.

### איך מוצאים את הקואורדינטות

הקואורדינטות הן `x,y,w,h` בפיקסלים של המקור: מרחק מהשמאל, מרחק מלמעלה, רוחב, גובה.

1. `--info` נותן את המידות האמיתיות של המקור.
2. פותחים את התמונה עם Read ומעריכים איפה כל דבר רגיש. אם התמונה הוצגה מוקטנת, מחשבים לפי היחס למידות האמיתיות.
3. מוסיפים שוליים של בערך 15% מכל צד. מלבן גדול מדי עדיף על אות אחת שנשארה.
4. מריצים עם `--blur` לכל אזור (אפשר כמה פעמים באותה פקודה).
5. **פותחים את התוצאה ב-`public/assets/` עם Read ובודקים בעיניים** שאי אפשר לקרוא אף ספרה ואף שם. נשאר משהו? מגדילים את המלבן ומריצים שוב עם `--force`.
6. מראים לבעל העסק את התוצאה המטושטשת לפני שהיא נכנסת לדף.

הטשטוש של הסקריפט לא הפיך: הוא ממצע את האזור לבלוקים גדולים, מוסיף רעש ומטשטש. לא מנסים לעשות את זה ב-CSS (`filter: blur`), כי אז המקור המלא יושב באתר וכל אחד יכול להוריד אותו.

## alt: התיאור לנגישות

- כותבים מה רואים ולמה זה בדף. לא "תמונה של".
  - לא טוב: "תמונה של אישה"
  - טוב: "דנה מדגימה תרגיל נשימה למתאמנת בסטודיו"
  - לצילום המלצה: "הודעת וואטסאפ ממתאמנת: 'אחרי חודש כבר אין לי כאבי גב'". מעתיקים את עיקר הטקסט שבתמונה, כי קורא מסך לא יכול לקרוא אותו מהתמונה.
- עד משפט אחד או שניים. בלי מילות מפתח לגוגל.
- תמונה שהיא רק קישוט (רקע, צורה, קו מפריד) מקבלת `alt=""`, ואז קורא מסך מדלג עליה.
- ה-alt נשמר ב-`site/content/copy.json` תחת `img.<שם-היעד>`. למשל `"img.herodana": "דנה מדגימה תרגיל נשימה למתאמנת בסטודיו"`. ככה בעל העסק יכול לתקן אותו במצב עריכה, בלי לגעת בקוד.

## כשחסרה תמונה: הנחיות צילום בטלפון

שולחים לבעל העסק את ההודעה הזו, מותאמת לתמונה שחסרה (מה צריך לראות בה ובאיזה כיוון, לפי images-list) ולפנייה שב-CLAUDE.md:

> כדי שהתמונה תיראה טוב בדף, ככה מצלמים בטלפון:
>
> - אור: ליד חלון, ביום. הפנים לכיוון החלון, לא עם הגב אליו. בלי פלאש ובלי מנורה צהובה מלמעלה.
> - רקע: קיר או חלל נקי. להזיז מהפריים כבלים, כוסות וערימות.
> - כיוון: <לאורך / לרוחב>, לפי מה שכתוב לתמונה הזו.
> - גובה: הטלפון בגובה העיניים של מי שמצולם. לא מלמטה ולא מלמעלה.
> - בלי זום. רוצים קרוב יותר? מתקרבים עם הרגליים.
> - לנגב את העדשה לפני, ולצלם 10–15 תמונות. נבחר את הטובה.
> - לשלוח את המקור: בוואטסאפ כ"מסמך" (לא כתמונה, כי אז הוא מכווץ אותה), במייל, או ב-AirDrop. לזרוק לתיקייה `images-inbox`.

## כשחסרה תמונה: מאגרים חינמיים

שני מאגרים עם רישיון ברור: [Unsplash](https://unsplash.com/license) ו-[Pexels](https://www.pexels.com/license/). לא לוקחים תמונות מגוגל, מאינסטגרם או מאתרים אחרים. לתמונה משם אין רישיון.

מה מותר בשניהם (נבדק מול דפי הרישיון ב-1.11.26): להוריד בחינם, להשתמש גם למטרה מסחרית (כולל דף נחיתה ומודעות), ולערוך (לחתוך, לשנות צבעים). קרדיט לצלם לא חובה, רק מומלץ.

מה אסור:

- בשניהם: למכור את התמונה כמו שהיא (פוסטר, מוצר) בלי שינוי משמעותי.
- Unsplash: לאסוף תמונות משם כדי לבנות שירות מתחרה. אם בתמונה יש אדם מזוהה, מותג או יצירה של מישהו אחר, ייתכן שצריך את הרשות שלו לשימושים מסוימים, והאחריות על המשתמש.
- Pexels: להציג אדם מזוהה באור רע או פוגעני, לרמוז שאדם או מותג בתמונה ממליצים על המוצר, להשתמש בתמונה כחלק מלוגו, סימן מסחרי או שם עסק, ולהעלות את התמונה לאתרי תמונות אחרים.
- תמונה ב-Unsplash שמסומנת Plus דורשת מנוי ולא נכללת ברישיון החינמי. מדלגים עליה.

הכללים המעשיים שלנו לדף:

- תמונה של אדם ממאגר אף פעם לא מוצגת כלקוח, כבעל העסק, כעובד או ליד המלצה. זה מטעה, וזה גם מה שהרישיון של Pexels אוסר.
- עדיפות לתמונות בלי פנים מזוהות ובלי לוגואים: ידיים בעבודה, חלל, חפצים, אווירה.
- קלוד מציע מילות חיפוש באנגלית ("pilates studio morning light", "hands kneading dough"). בעל העסק מוריד בעצמו וזורק ל-`images-inbox/`.
- ב-images-list רושמים ליד התמונה את הלינק לעמוד שלה ואת שם הצלם, כדי שיהיה ברור מאיפה היא ובאיזה רישיון.
- תנאי הרישיון יכולים להשתנות. לפני שממליצים, לפתוח שוב את שני דפי הרישיון (WebFetch) ולבדוק שלא השתנה משהו מהותי.

## גרפיקה שקלוד בונה בעצמו

הרבה פעמים זה עדיף על תמונת מאגר, כי זה במותג ומדויק לדף:

- אייקונים: SVG פשוט בקוד, בצבעים מ-`brand`. אייקון שעומד ליד טקסט שאומר את אותו דבר מקבל `aria-hidden="true"`.
- מוקאפים: מסגרת של טלפון או מחשב ב-SVG או CSS, ובתוכה צילום מסך אמיתי של המוצר (שעבר את הסקריפט). למשל המסך של הקורס, הטופס או הדשבורד.
- רקעים: מעברי צבע, רשת עדינה, צורות. ב-CSS כשאפשר, ואם לא, SVG קטן ב-`public/assets/`.
- תרשימים: שלבי התהליך, לפני ואחרי, ציר זמן. כ-SVG או HTML, כדי שהטקסט בהם יהיה טקסט אמיתי (נקרא, ניתן לעריכה, נגיש).

SVG לא עובר דרך `npm run images`. הוא קטן מלכתחילה. SVG שמעביר מידע מקבל `role="img"` ו-`aria-label`, ו-SVG קישוטי מקבל `aria-hidden="true"`.
