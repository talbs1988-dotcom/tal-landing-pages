# GitHub: איפה הדף שמור, ואיך כל שינוי מגיע לאוויר

הדרך המקצועית, כמו שעובדים בחברות: קוד הדף שמור במאגר פרטי ב-GitHub, ו-Vercel מעלה לאוויר את מה שנכנס לגרסה הראשית (`main`). כל שינוי אחרי ההעלאה הראשונה עובר דרך ענף נפרד, קישור תצוגה ואישור, ורק אז נכנס לדף החי.

נבדק מקצה לקצה על דף ניסיון אמיתי ב-3.11.26: מאגר פרטי, חיבור ל-Vercel, העלאה ראשונה, עדכון דרך ענף ו-PR, קישור התצוגה מהתגובה של Vercel, בנייה מחדש של הגרסה החיה (`redeploy`), שומר הסודות, ושחזור במחשב אחר.

**מה בעל העסק מקבל מזה, במילים שלו:**

- קוד הדף שמור גם מחוץ למחשב. המחשב מת? מורידים אותו מ-GitHub למחשב חדש. (תיקיית העסק עצמה, עם הקופי והמותג, לא שמורה שם. ראו ט.)
- כל שינוי נשמר כגרסה. משהו נשבר? חוזרים לגרסה הקודמת.
- כל שינוי נבדק בקישור תצוגה לפני שלקוחות רואים אותו.

## חוקים שלא עוקפים

1. **שום קוד סודי לא נכנס ל-GitHub.** הסודות (כתובת הוובהוק, הטוקן של מטא, הגיבוי) יושבים רק בהגדרות הפרויקט ב-Vercel. בתבנית יש שלוש שכבות, וכולן נשארות דלוקות:
   - `.gitignore` לא מכניס קבצי סביבה, `.vercel`, מפתחות וגיבויי לידים.
   - **שומר הסודות** (`scripts/secret-guard.mjs`) רץ לבד לפני כל שמירה, ולפני כל העלאה על כל הגרסאות שעולות. הוא חוסם קובץ סביבה וכל דבר שנראה כמו קוד סודי, ולא מדפיס את הסוד.
   - לפני כל העלאה קלוד מריץ גם `npm run guard` בעצמו, ומראה את התוצאה.
2. **אסור:** `--no-verify`, `git add -f`, `git push --force`, לשנות או למחוק את `.githooks`, ולשנות את `core.hooksPath`. השומר חסם? מתקנים את הסיבה. לא עוקפים, גם אם בעל העסק מבקש "רק להעלות".
3. **המאגר תמיד פרטי.** בודקים אחרי היצירה (ד5). ציבורי → עוצרים ולא מעלים.
4. **רק `main` הוא הדף החי.** העלאה ישירה ל-`main` קורית פעם אחת בלבד, בהעלאה הראשונה, כשאין בו עדיין כלום (`git ls-remote origin main` ריק). מכאן כל שינוי עובר דרך ענף ו-PR (ז).
5. **המאגר הוא תיקיית האתר בלבד** (`$SITE`). האפיון, הקופי, המותג והמשפטי לא נכנסים אליו.
6. **כל פקודה של git ו-`gh` רצה מתוך `$SITE`** (`cd '<$SITE>' && ...`). החריג היחיד: ההורדה למחשב חדש (ט4), כי אז `site` עוד לא קיים.
7. **קלוד לא פותח חשבון ולא מקליד סיסמה.** ההרשמה וההתחברות הן של בעל העסק. קלוד לא מוחק מאגר, ענף `main` או גרסה, ולא משנה הגדרות חשבון.

## א. כלים

בודקים, ומתקינים רק מה שחסר:

1. `git --version` → מספר גרסה.
   - **במק** אין git → `xcode-select --install`. בעל העסק מריץ את זה בטרמינל משלו, ובחלון שנפתח לוחץ **Install** ואז **Agree**. ההתקנה לוקחת כמה דקות. לפעמים החלון נפתח לבד כבר בפקודה הראשונה של git, וזה אותו דבר.
   - **בווינדוס** → מורידים מ-https://git-scm.com/downloads/win ומתקינים עם כל ברירות המחדל: Next עד הסוף. אחר כך סוגרים את קלוד ופותחים מחדש.
2. `gh --version` → מספר גרסה. זה הכלי שדרכו קלוד מדבר עם GitHub.
   - חסר → מורידים מ-https://cli.github.com, הכפתור הגדול למק או לווינדוס, ומתקינים כמו כל תוכנה. במק שיש בו Homebrew אפשר גם `brew install gh`. אחר כך סוגרים את קלוד ופותחים מחדש.
3. לא ממשיכים עד ששתי הפקודות מחזירות מספר גרסה.

## ב. חשבון והתחברות

1. `gh auth status`.
   - מחובר → `gh api user --jq .login`, ולשאול: "המחשב מחובר ל-GitHub בתור <שם>. זה החשבון שלכם, שבו הדף צריך להישמר?" לא → `gh auth logout --hostname github.com --user '<שם>'` (בהסכמה) ו-2.
   - לא מחובר → 2.
2. **אין חשבון:** "צריך חשבון ב-GitHub. שם קוד הדף יישמר. נרשמים ב-https://github.com/signup. הכי פשוט: Continue with Google, עם החשבון של העסק. כתבו לי כשסיימתם." קלוד לא פותח את החשבון.
3. **התחברות:** בעל העסק מריץ בטרמינל משלו (כמו ב-`/page-live`, "פקודה שבעל העסק מריץ בעצמו"):

   `gh auth login --hostname github.com --git-protocol https --web`

   | מה מופיע                                         | מה עושים                                                    |
   | ------------------------------------------------ | ----------------------------------------------------------- |
   | `Authenticate Git with your GitHub credentials?` | Y (Enter)                                                   |
   | קוד בן 8 תווים, ו-`Press Enter to open...`       | מעתיקים את הקוד, לוחצים Enter. נפתח דפדפן                   |
   | בדפדפן: Device Activation                        | **Continue**, מדביקים את הקוד, **Continue**                 |
   | בדפדפן: Authorize GitHub CLI                     | **Authorize github**. אם מבקשים סיסמה או קוד אימות, מקלידים |
   | בטרמינל: `Logged in as <שם>`                     | כותבים לי "סיימתי"                                          |

   הקוד בן 8 התווים הוא חד-פעמי, ותקף רק כמה דקות. הוא לא נכנס לצ'אט, וגם לא צריך.

4. אחרי "סיימתי": `gh auth status` → מחובר, ו-`gh auth setup-git` (מחבר את git לאותה התחברות). שוב `gh api user --jq .login`, ולוודא שזה החשבון הנכון.

## ג. זהות לשמירות

**רק בתוך מאגר:** אחרי `git init` (ד2) או אחרי ההורדה למחשב חדש (ט5). מחוץ למאגר הפקודה נכשלת. כל שמירה ב-git רשומה על שם, ומשתמשים בכתובת הפרטית ש-GitHub נותן, כדי שהמייל האמיתי לא יופיע:

`cd '<$SITE>' && git config user.name '<login>' && git config user.email "$(gh api user --jq '.id')+<login>@users.noreply.github.com"`

בווינדוס ב-PowerShell: `;` במקום `&&`. `$(...)` עובד גם שם.

## ד. מאגר לדף

כל צעד נבדק לפני שעושים אותו, ומדלגים רק על מה שכבר נעשה. ככה זה עובד גם בפעם הראשונה, גם בהמשך אחרי שיחה שנקטעה, וגם בדף שעלה פעם בדרך הישנה (העלאה ישירה מהמחשב) ועכשיו עובר ל-GitHub.

1. **שמות:** שם הפרויקט ב-Vercel = שם המאגר, כברירת מחדל (`<שם>`). אם המאגר מקבל שם אחר (ד4), רושמים את שניהם, ומכאן משתמשים בשם של כל אחד במקום שלו.
2. **git:** `test -d '<$SITE>/.git' && echo yes`. אין → `cd '<$SITE>' && git init -b main`. ואז ג (זהות).
3. **שומר הסודות:** `cd '<$SITE>' && node scripts/secret-guard.mjs install` → `שומר הסודות מחובר ✓`. ואז `cd '<$SITE>' && git config core.hooksPath` → `.githooks`, ו-`git add --chmod=+x .githooks/pre-commit .githooks/pre-push` (כדי שהשומר יעבוד גם במחשב אחר). לא מחובר → לא ממשיכים.
4. **המאגר ב-GitHub:** `cd '<$SITE>' && git remote get-url origin`.
   - מחזיר כתובת → המאגר כבר קיים. לוקחים ממנה את `<login>/<מאגר>`.
   - שגיאה → יוצרים: `cd '<$SITE>' && gh repo create '<login>/<שם>' --private --source . --remote origin`.
   - "Name already exists" → יש כבר מאגר בשם הזה. לא משתמשים בו ולא מוחקים אותו. לשאול: "יש לכם כבר מאגר בשם <שם>. לקרוא למאגר של הדף <שם>-2?"
5. **פרטי?** `cd '<$SITE>' && gh repo view --json visibility --jq .visibility` → `PRIVATE`. כל דבר אחר → לעצור. בעל העסק משנה ל-Private: המאגר ב-GitHub ← **Settings** ← למטה **Change visibility** ← **Make private**. ובודקים שוב.
6. **החיבור ל-Vercel:** `cd '<$SITE>' && npx vercel@latest git connect --yes` → `Connected` (גם כשכבר מחובר, זה בטוח להריץ שוב).
   - נכשל (בדרך כלל: ל-Vercel אין הרשאה למאגר הזה) → בעל העסק מחבר בדפדפן: Vercel ← הפרויקט ← **Settings** ← **Git** ← **Connect Git Repository** ← **GitHub**. אם GitHub שואל איפה להתקין את Vercel: בוחרים את החשבון, ואז **Only select repositories** ← בוחרים את המאגר ← **Install**. **בדף השני והלאה** GitHub לא שואל שוב, והמאגר החדש לא ברשימה: GitHub ← התמונה למעלה ← **Settings** ← **Applications** ← Vercel ← **Configure** ← מוסיפים את המאגר ← **Save**. כתבו לי "חיברתי", ואז מריצים שוב את `git connect` כדי לוודא.

## ה. מה עולה, ובדיקה לפני כל העלאה

גם בפעם העשירית:

1. `cd '<$SITE>' && git add -A && git status --short` (שמות בלבד). בודקים ברשימה:
   - אין שום שם שמתחיל ב-`.env`, ואין `.vercel/`, `node_modules/`, `.next/`.
   - **רק בשמירה הראשונה:** יש `package.json`, `site.config.ts`, `app/`, `.githooks/`, `scripts/secret-guard.mjs`. בשמירות הבאות מופיעים רק הקבצים שהשתנו, אז בודקים ככה שהם עדיין במאגר: `cd '<$SITE>' && git ls-files package.json site.config.ts scripts/secret-guard.mjs .githooks` → ארבע שורות לפחות.
   - משהו לא תקין → `cd '<$SITE>' && git reset -q` ומתקנים (`.gitignore`, או מוציאים את הקובץ). לא ממשיכים.
   - הרשימה ריקה → אין מה לשמור. לא שומרים.
2. `cd '<$SITE>' && git commit -m '<מה השתנה, בעברית>'`. השומר רץ לבד. חסם → ההודעה אומרת איזה קובץ ולמה. מתקנים את הסיבה ומנסים שוב.
3. `cd '<$SITE>' && npm run guard` → `שומר הסודות: נקי ✓`. להראות לבעל העסק את השורה הזו.

## ו. העלאה ראשונה

רק כש-`cd '<$SITE>' && git ls-remote origin main` מחזיר שורה ריקה. מחזיר משהו → הדף כבר ב-GitHub, וכל שינוי עובר דרך ז.

1. ה1–ה3.
2. `cd '<$SITE>' && git push -u origin main`. השומר רץ שוב לפני ההעלאה.
3. **מחכים ל-Vercel:** `cd '<$SITE>' && gh api 'repos/<login>/<מאגר>/commits/main/status' --jq .state`. בודקים כל 10 שניות:
   - `success` → הבנייה הצליחה.
   - `pending` → עוד בונה. **5 דקות ועדיין `pending`, או שאין שום תשובה** → כנראה ל-Vercel אין הרשאה למאגר, ולכן הוא לא שמע על השמירה. חוזרים ל-ד6 (כולל "בדף השני והלאה"), ואז שמירה ריקה כדי ש-Vercel יבנה. **בהעלאה הראשונה בלבד:** `cd '<$SITE>' && git commit --allow-empty -m 'בנייה מחדש' && git push`. **אחרי מיזוג (ז8):** לא שומרים ישר ל-`main`. השמירה הריקה עוברת דרך ז1–ז8 כמו כל שינוי.
   - `failure` או `error` → `cd '<$SITE>' && gh api 'repos/<login>/<מאגר>/commits/main/status' --jq '.statuses[].target_url'` נותן קישור ליומן הבנייה ב-Vercel. **קודם קוראים מה כתוב שם.** שגיאת בנייה → `npm run build` במחשב מראה אותה. כתוב שם "Blocked", או שהבנייה חסומה בגלל מי ששמר (commit author) → Vercel ← Account Settings ← **Authentication** ← לחבר את GitHub, ואז שמירה ריקה כמו למעלה (בהעלאה הראשונה ישר, אחרי מיזוג דרך ז).
4. **הדף החי מתעדכן כמה שניות אחרי ה-`success`.** `curl` לכתובת, ואם עוד מקבלים את הגרסה הקודמת, מנסים שוב אחרי 15 שניות, עד דקה.

## ז. אחרי שהדף באוויר: כל שינוי בקבצים

תמיד ככה. גם תיקון של מילה אחת, גם הכתובת החדשה, גם קוד האימות של גוגל, וגם שינוי ב-`site.config.ts` אחרי `sync-business`:

1. **מתחילים מהגרסה החיה:** `cd '<$SITE>' && git switch main && git pull -q && git status --short`. צריך לצאת ריק, חוץ מהשינוי שעומד להיעשות. יש קבצים אחרים ששונו ולא נשמרו → לא ממשיכים. מראים לבעל העסק את השמות ושואלים מה הם.
2. **ענף:** `cd '<$SITE>' && git switch -c 'update-<מילה באנגלית>-<תאריך, למשל 0311>'`.
3. עושים את השינוי. ואז `cd '<$SITE>' && npm run build` → עובר.
4. ה1–ה3, ואז `cd '<$SITE>' && git push -u origin '<הענף>'`.
5. **PR:** `cd '<$SITE>' && gh pr create --base main --head '<הענף>' --title '<מה השתנה>' --body '<במשפט אחד>'`.
6. **קישור תצוגה:** מחכים ל-`success` כמו ב-ו3, עם שם הענף במקום `main`: `cd '<$SITE>' && gh api 'repos/<login>/<מאגר>/commits/<הענף>/status' --jq .state`. ואז הקישור מהתגובה ש-Vercel כותב ב-PR:
   `cd '<$SITE>' && gh pr view '<הענף>' --json comments --jq '[.comments[].body | scan("https://[a-z0-9-]+\\.vercel\\.app")] | unique[]'`
   הקישור מוגן. רק מי שמחובר לחשבון Vercel של העסק רואה אותו, וזה בכוונה.
7. **לבעל העסק:** "השינוי מוכן בקישור תצוגה: <קישור>. פותחים אותו (אם מבקשים, מתחברים לחשבון Vercel שלכם) ובודקים איך זה נראה. בקישור הזה הטופס לא שולח, וזה בכוונה: הלידים מחוברים רק לדף החי. ללקוחות עוד לא השתנה כלום. להעלות לדף החי?" **מחכים ל"כן".**
8. **כן** → `cd '<$SITE>' && gh pr merge '<הענף>' --merge --delete-branch`, ואז `cd '<$SITE>' && git switch main && git pull -q`. מחכים ל-`success` על `main` (ו3), ובודקים בדף החי כמו ו4.
   - **המיזוג נכשל** ("not mergeable", או התנגשות) → בדרך כלל כי `main` השתנה בינתיים. `cd '<$SITE>' && git switch '<הענף>' && git fetch -q origin && git merge origin/main`. אין התנגשות → git כבר יצר את שמירת המיזוג, אז רק `cd '<$SITE>' && git push`, ה3, וחוזרים ל-6. יש התנגשות → `git merge --abort`, ולומר לבעל העסק במשפט מה התנגש. לא מכריעים בעצמנו מה נשאר.
9. **לא, צריך תיקון** → מתקנים באותו ענף, ושוב 4 ו-6–7. **לא רוצים בכלל** → `cd '<$SITE>' && gh pr close '<הענף>' --delete-branch && git switch main`.

**שינוי שהוא רק בהגדרות ב-Vercel** (משתנה סביבה חדש או מחוק, למשל ב-`/page-connect`), ושום קובץ ב-`$SITE` לא השתנה: אין מה לשמור ב-git. כדי שהשינוי ייכנס לתוקף, בונים מחדש את הגרסה החיה:
`cd '<$SITE>' && npx vercel@latest redeploy 'https://<שם הפרויקט>.vercel.app' --environment production` → `Ready`. ואז `curl` לבדיקה. השתנה גם קובץ? אז לא `redeploy` (הוא בונה את הקוד הישן). הכול עולה דרך 1–8, וזה מכניס לתוקף גם את ההגדרות.

## ח. חזרה לגרסה קודמת

משהו נשבר בדף החי:

1. **מהר, בלי לגעת בקוד:** Vercel ← הפרויקט ← **Deployments** ← הגרסה הקודמת שעבדה ← שלוש הנקודות ← **Instant Rollback** ← **Confirm**. הדף חוזר תוך שניות. בחבילה החינמית אפשר לחזור רק לגרסה אחת אחורה.
2. **חשוב:** אחרי חזרה כזו Vercel **מפסיק לעדכן את הדף החי לבד**, גם כשנכנס שינוי ל-`main`. לכן חייבים את 3 ו-4.
3. **מסדרים את הקוד:** ז1–ז2, ואז `cd '<$SITE>' && git log --oneline --merges -5` מראה את המיזוגים האחרונים. מבטלים את המיזוג ששבר: `cd '<$SITE>' && git revert --no-edit -m 1 '<המזהה>'`. ממשיכים מ-ז3 (בנייה, PR, קישור תצוגה, אישור, מיזוג).
4. **מחזירים את העדכון האוטומטי:** אחרי המיזוג ו-`success` על `main`: `cd '<$SITE>' && npx vercel@latest ls '<שם הפרויקט>' --prod`, הכתובת הראשונה ברשימה היא הגרסה החדשה. ואז `cd '<$SITE>' && npx vercel@latest promote '<הכתובת הזו>' --yes`. בודקים בדף החי כמו ו4. מכאן Vercel חוזר לעדכן לבד.

## ט. מחשב חדש

**מה שמור ב-GitHub:** קוד הדף בלבד. **מה לא:** תיקיית העסק (CLAUDE.md, המותג, הקופי, המשפטי, והמצב של כל שלב). לכן ממליצים לבעל העסק, כבר בשלב 6: "כדאי לשמור עותק של תיקיית העסק בגוגל דרייב או ב-iCloud, חוץ מהתיקייה `site` של כל דף (היא כבר ב-GitHub, ויש בה קבצים כבדים)." עם העותק הזה השחזור מלא. בלעדיו, משחזרים רק את הדף.

1. מתקינים את Claude Code, את Node ואת הסיסטם, כמו בפעם הראשונה. ואז את הכלים מ-א, ומתחברים כמו ב-ב.
2. **יש עותק של תיקיית העסק** → מחזירים אותו למחשב, ובכל דף התיקייה `site` ריקה או חסרה. ממשיכים מ-4.
3. **אין עותק** → `/page-start` יוצר מחדש את תיקיית העסק ואת תיקיית הדף, באותם שמות. **לא ממשיכים בו לבניית האתר.** את CLAUDE.md, המותג ו-`legal/business.md` ממלאים מחדש מהדף החי (קלוד קורא אותו), ובעל העסק מאשר. בלי זה, `sync-business` בשלב הבא היה מכניס לאתר `[למלא]`.
4. **ההורדה, בתיקיית הדף** (החריג היחיד לחוק 6): `cd '<תיקיית הדף>' && gh repo clone '<login>/<מאגר>' site`. את שם המאגר לוקחים משורת ההחלטות ב-CLAUDE.md, או מ-`gh repo list --limit 50`.
5. `cd '<$SITE>' && npm install`. השומר מתחבר לבד (`שומר הסודות מחובר ✓`). לוודא: `cd '<$SITE>' && git config core.hooksPath` → `.githooks`. ואז ג (זהות).
6. **Vercel:** בעל העסק בטרמינל משלו: `cd '<$SITE>' && npx vercel@latest login`. ואז `cd '<$SITE>' && npx vercel@latest project ls`, ובודקים שהפרויקט מופיע. את השם לוקחים משורת ההחלטות ב-CLAUDE.md, לא מניחים שהוא שם המאגר. ואז `cd '<$SITE>' && npx vercel@latest link --yes --project '<שם הפרויקט>'`. **אותו שם בדיוק**, כדי להתחבר לפרויקט הקיים ולא ליצור חדש.
7. **המצב של השלבים** (רק אם אין עותק, ו-`.page/status.json` נוצר מחדש): מסמנים את השלבים שהדף כבר עבר, לפי הסדר, עם `node '$SCRIPTS/status.mjs' set '<תיקיית הדף>' <שלב> done 'שוחזר מ-GitHub'`. לדף שבאוויר ומחובר: start, brief, copy, design, legal, check, live, connect. מראים לבעל העסק את `status.mjs show` לפני שממשיכים.
8. מכאן ממשיכים כרגיל. כל שינוי עובר דרך ז.

הסודות לא צריכים שחזור. הם מעולם לא היו במחשב, הם יושבים ב-Vercel.
